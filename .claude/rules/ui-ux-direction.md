# UI/UX direction

**Mirror Wave's proven information architecture and flow** (dashboard → invoices list → create
invoice → clients → settings; the same screen sequence and interaction patterns users already
know from Wave) — but build **original visual design**: our own layout details, components, type,
and color palette, not a pixel-level reskin of Wave's actual screens with only colors swapped.

Why the distinction matters: copying a specific competitor's exact UI (not just the general
invoicing-app patterns that are common across the category) risks trade-dress/design-copying
issues and app-store review flags for being "too similar" to an existing app — a real risk, not a
theoretical one, given how literally "same UI just recolor it" reads. Reusing proven UX *structure*
(what screen comes after what, where actions live) carries none of that risk — most invoicing apps
already converge on similar structure because it's what works for the task, not because it's IP.

If a specific Wave screen's exact layout is wanted as a closer reference for a specific flow, name
that screen when it comes up so it can be evaluated case by case, rather than treating "clone Wave,
change colors" as a blanket instruction.
